# 提示词催化剂：改变 AI 处理任务的方式

> 源：PDF 第 5 章《提示词催化剂》《五类最实用的提示词催化剂》《方法名不是魔法》
> 催化剂不给 AI 增加知识，只改变它组织答案的路线。五要素解决"做什么"，催化剂解决"怎么做"。

## 1. 解释类：控制答案的理解难度
- 先讲直觉，再讲正式定义
- 用大白话解释
- 每个专业术语第一次出现时都解释
- 使用一个最小例子
- 用生活中的场景类比
- 每次只引入一个新概念

## 2. 拆解类：让 AI 先建立问题结构
- 先拆解问题，再逐项处理
- 按照输入、处理过程、输出进行分析
- 列出完整因果链
- 区分必要条件和充分条件
- 先列可能原因，再判断最可能的原因
- 从最基本的问题开始

## 3. 严谨类：暴露前提和不确定性
- 区分已知事实、合理推测和无法确认的部分
- 列出结论依赖的前提
- 说明结论的适用范围和边界条件
- 找出隐藏假设
- 给出最强的反方观点
- 对推荐结论执行独立反方审查
- 说明还缺少哪些证据

注意：不迷信"87%"式置信度数字。更实用的是让 AI 说明：为什么不确定、
缺少什么信息、怎样进一步验证。

### 独立反方审查

任务要求推荐、筛选候选方案或反驳指定方案时，把下面整组动作视为一个严谨类催化剂。只比较时不触发；对全部候选项逐项、对称地列出反方观点仍属于只比较。

1. 匹配审查目标：推荐审查针对初步推荐；筛选审查针对初步候选集及纳入/排除阈值；当用户把一个明确指定的方案或既有结论作为非对称攻击对象时，匹配指定方案反驳，即使用户不要求判断原结论是否改变；不凭空增加推荐或替代方案比较，并尊重用户禁止改判结论的边界。
2. 支持多 agent 时，派发一个未参与初步分析的子 agent，只让它攻击待审查结果并找出隐藏假设、最强反例、失败条件和改选/改筛阈值。
3. 环境不支持子 agent 时，主分析者在初步结果后单独执行同一份红队审查。
4. 主分析者吸收审查结果，说明反驳是否成立，以及最终推荐是否改变、候选集是否改变或原判断是否改变，不直接粘贴审查者原文。

## 4. 验证类：要求 AI 主动检查结果
- 使用另一种方法重新计算
- 将结果代回原式验证
- 检查零值、负数和极端情况
- 寻找一个能够推翻结论的反例
- 逐项核对是否满足需求
- 编写并运行测试
- 对照原始材料检查引用

注意：AI 自检 ≠ 外部验证。代码靠跑测试/构建/看日志，论文靠查原文，
计算靠代入复算。催化剂促使检查，不替代真实证据。

## 5. 执行类：把分析变成可以落地的动作
- 给出最小可行方案
- 优先采用最小修改
- 按优先级排列
- 给出具体操作步骤
- 明确验收标准
- 提供验证方法
- 说明失败后如何回滚
- 给出下一步行动

## 方法名 → 具体动作翻译表

方法名不是魔法，只写名字效果不稳定，转写时必须翻译成动作：

| 方法名 | 翻译成的具体动作 |
| --- | --- |
| 第一性原理 | 先列出已确认的事实、不可改变的约束和未经验证的假设；暂时忽略现有方案，从这些基础条件重新推导可行路线 |
| 批判性思维 | 找出方案依赖的三个隐藏假设；涉及推荐、筛选或指定方案反驳时执行独立反方审查，给出最强反方观点，并说明它最可能在哪些条件下失败 |
| 费曼学习法 | 假设给没有相关基础的人讲解：避免堆术语，先用日常语言解释，再给一个最小例子，最后提一个问题检查对方是否真正理解 |
| 奥卡姆剃刀 | 优先给出依赖假设最少的解释/方案，并说明为什么更复杂的版本不必要 |
| 苏格拉底式提问 | 不直接给答案，通过连续提问引导我自己得出结论，每次只问一个问题 |
| 红队视角 | 假设你的任务是攻破这个方案：找出最薄弱的三个点及可行的利用方式 |
| 帕累托最优 | 找出用最小成本覆盖大部分需求的方案，并明确说明放弃了哪些收益 |

（前三条为 PDF 原文翻译，后四条按同一原则扩展。）

## 用量纪律

- 一个任务选 1-3 个催化剂，多了会互相冲突（简单解释 vs 展开批判 vs 极限精简）。
- 按任务类型选配方见 recipes.md。
- AI 回答不理想时的自诊断：太难→加解释类；跳结论→加拆解类；
  猜测当事实→加严谨类；只给结论没验证→加验证类；分析多无法落地→加执行类。
