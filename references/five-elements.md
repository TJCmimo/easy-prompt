# 五要素：一条高效提示词的骨架

> 源：PDF 第 4 章《Prompt 新手只需要掌握 5 个要素》、第 5 章《把催化剂加入五要素》

## 五要素定义

| 要素 | 回答的问题 | 示例 |
| --- | --- | --- |
| 目标 | 我要你做什么？看什么、怎么看、看到什么程度 | 定位装甲板识别掉帧原因，先分析，不改代码 |
| 背景 | 我是谁？什么水平？什么场景？ | RM 视觉组新生，C++ 基础一般 |
| 输入 | 代码、报错、日志、截图、需求是什么？ | <粘贴 CMake 报错全文> |
| 限制 | 不要做什么？不能改什么？输出多长？ | 先不要改代码；不要建议重装环境 |
| 验收 | 什么结果算完成？ | 按概率排序的原因清单 + 每项验证命令 |

## 第六可选要素：处理方法

复杂任务可加入"处理方法"一项，写明希望 AI 用哪些催化剂（见 catalysts.md），
每次 1-3 个，不堆砌。

## 缺口诊断表（转写时逐项对照）

| 要素 | 缺失时的处理 | 分级 |
| --- | --- | --- |
| 目标 | 模糊或多解（"优化""看看"）→ 反问选择题 | 关键缺口 |
| 任务类型 | 无法判别五类归属（见 recipes.md）→ 反问 | 关键缺口 |
| 背景 | 默认"RM 新生、相应方向基础一般"+ 标【推断】 | 次要缺口 |
| 输入 | 留 <粘贴代码/报错/截图> 占位符，解说里提醒 | 次要缺口 |
| 限制 | 按任务类型给安全默认（见 recipes.md）+ 标【推断】 | 次要缺口 |
| 验收 | 按任务类型推断 + 标【推断】 | 次要缺口 |

反问规则：只对关键缺口反问；一次问完，最多 1-3 个选择题；不逐项审讯。

## 写法要领（源自 PDF 第 5 章）

- 信息密度高优于长：可以长但不要乱，可以多但要分层，无关情绪不进提示词。
- 背景不是废话：它决定 AI 用什么难度回答。
- 长对话中核心要求会被稀释：需要时在提示词开头加重置锚点
  "现在切换任务，忽略前文风格，以下只以本条为准"。
