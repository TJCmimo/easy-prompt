# 五要素：一条高效提示词的骨架

> 源：PDF 第 4 章《Prompt 新手只需要掌握 5 个要素》、第 5 章《把催化剂加入五要素》

## 五要素定义

| 要素 | 回答的问题 | 示例 |
| --- | --- | --- |
| 目标 | 我要你做什么？看什么、怎么看、看到什么程度 | 比较三种通勤方案，给出适用条件，先不预设结论 |
| 背景 | 哪些用户或场景事实会实质改变回答？ | 读者第一次看 A/B 测试报告，统计基础一般 |
| 材料 | 完成任务要依据哪些代码、数据、文本、截图、记录或需求？ | <粘贴活动报名数据、字段说明与已有观察> |
| 限制 | 不要做什么？不能改什么？输出多长？ | 每月预算不超过 500 元；最多投入 3 名志愿者 |
| 验收 | 什么结果算完成？ | 一份可直接发布的公告，逐项覆盖时间、地点与报名方式 |

## 第六可选要素：处理方法

复杂任务可加入"处理方法"一项，写明希望 AI 用哪些催化剂（见 catalysts.md），
每次 1-3 个，不堆砌。

## 背景的边界与删除测试

- 用户个人背景：身份、能力、偏好。
- 任务场景背景：受众、既有环境和组织场景等描述性事实。
- 完成任务所需上下文：代码和数据放入 `材料`；预算、人手、时间等资源上限及禁止事项放入 `限制`；完成标准放入 `验收`。不要把这些信息塞进背景。

`背景` 是条件字段。删除候选背景后，如果解释难度、方案选择、风险边界或输出对象仍基本不变，成品就省略整行。背景必须提供增量信息，不得复述已在 `目标` 或 `材料` 中表达的信息。只保留用户明确提供或可由任务直接确定的事实，不根据 skill 来源、任务领域或语气推断用户身份和能力。

## 缺口诊断表（转写时逐项对照）

| 要素 | 缺失时的处理 | 分级 |
| --- | --- | --- |
| 目标 | 模糊或多解（"优化""看看"）→ 反问选择题 | 关键缺口 |
| 任务类型 | 因信息不足或多类歧义无法判别五类归属→反问；目标明确但五类均不匹配→走 SKILL.md 的零类出口 | 前者为关键缺口；后者非缺口 |
| 背景 | 先做删除测试；相关且已明确→保留；缺失且会导致明显不同成品→反问；否则省略 | 条件项 |
| 材料 | 留 <粘贴代码/报错/截图> 占位符，解说里提醒 | 次要缺口 |
| 限制 | 保留已知资源上限和禁止事项；其余按任务类型给安全默认（见 recipes.md）+ 标【推断】 | 次要缺口 |
| 验收 | 按任务类型推断 + 标【推断】 | 次要缺口 |

反问规则：只对关键缺口反问；背景只有在不同取值会产生明显不同成品时才升级为关键缺口。一次问完，最多 1-3 个选择题；不逐项审讯。

## 写法要领（源自 PDF 第 5 章）

- 信息密度高优于长：可以长但不要乱，可以多但要分层，无关情绪不进提示词。
- 有效背景不是废话，但背景也不是必填槽位：只保留会改变回答的事实。
- 长对话中核心要求会被稀释：需要时在提示词开头加重置锚点
  "现在切换任务，忽略前文风格，以下只以本条为准"。
